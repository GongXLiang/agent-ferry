# 任务书模板

复制后填写，删掉不适用的行，存成 UTF-8 文件，用 `run --prompt-file <文件>` 传入。任务书要能独立读懂：被委托方看不到你和用户之前的对话。

```markdown
# 任务：<一句话说明要做什么>

## 目标与边界
- 要回答或完成：<具体问题或交付物>
- 允许修改：<文件/目录；只读任务写「不修改任何文件」>
- 不处理：<相邻但这次不做的事>

## 完成标准
- <可观察的结果，例如：给出三个候选方案及取舍；某测试从失败变为通过>
- 非零退出或某项检查失败是否算任务失败：<说明>

## 入口线索
- <1–4 个已确认的相关文件或链接；其余让被委托方自己探索>

## 验证方式
- <真实的命令，例如 python -m pytest tests/test_x.py -q；不要写空泛的「运行测试」>

## 回报格式
- 结论（先说结论）
- 改动的文件与原因（如有）
- 执行过的验证命令及结果原文
- 证据与来源（文件:行号或链接）
- 未完成、未验证或被阻塞的事项
```

## 可选片段

按任务性质追加到「目标与边界」或「回报格式」之后。

**先核实前提**

> 先检查这项请求依赖的前提是否成立（事件是否真的发生、文件或接口是否存在、版本是否匹配）。前提不成立或无法确认时，先说明并停下，不要假设它成立。

**区分事实、报道与推断**

> 回报时把每条结论标为：已核实的事实（附来源）、媒体或他人的报道（注明出处和时间）、你的推断（说明依据）。不要把推断写成事实。

**引用来源**

> 每条关键结论都附可核对的来源：网页给出标题、链接和访问日期；代码给出文件路径和行号。找不到来源的结论标为「未找到来源」。

## 写作提示

- 一次只交代一个任务；大任务拆成几次委托，每次都能独立验收。
- 缺少仓库事实时先自己查清楚，不要让被委托方猜。
- 需要它读的大段材料放进文件，用 `--file` 指给它，而不是全部塞进提示词。
- 不要在任务书里放密钥、令牌或与任务无关的私人信息：这些内容会发给第三方模型服务。
